------------------------------------------------------------
18.1 CLOSED-BAR LAW
------------------------------------------------------------

Използват се само ЗАТВОРЕНИ свещи.
Свещ е затворена, когато SERVER_TIME ≥ close_time + 1 ms.

Стойност от по-висок timeframe е видима на по-нисък timeframe
едва от първата свещ, чийто open_time ≥ close_time на HTF свещта.

------------------------------------------------------------
18.2 CANDLE BOUNDARIES
------------------------------------------------------------

Всички времена са UTC, в милисекунди (Binance open_time).

1M/5M/15M/1H/4H — граници според Binance klines.
D1 — 00:00:00.000 UTC.
W1 — понеделник 00:00:00.000 UTC.

Смесване на граници от различни източници = CONFLICT.

------------------------------------------------------------
18.3 EVENT TIME SEMANTICS
------------------------------------------------------------

Всяко събитие има задължително:

FORMATION_TIME    — open_time на първата свещ от модела.
CONFIRMATION_TIME — close_time на свещта, след която събитието
                    е известно без бъдеща информация.
AVAILABLE_FROM    — първият момент, в който системата има право
                    да го използва (= CONFIRMATION_TIME + 1 ms).

Swing pivot с R свещи вдясно:
CONFIRMATION_TIME = close_time на R-тата свещ след pivot-а.

Backtest, gate или decision може да чете събитие само ако
decision_time ≥ AVAILABLE_FROM. Нарушение = G2 FAIL.

------------------------------------------------------------
51.1 EVENT ID RECIPE
------------------------------------------------------------

EVENT_ID = "ev_" + hex(SHA-256(CANONICAL_PAYLOAD))

CANONICAL_PAYLOAD = UTF-8 JSON, ключове сортирани по азбучен ред,
без интервали, със следните полета:

  event_type
  detector_id
  detector_version
  params            (обект, ключове сортирани)
  source            ("BINANCE_FUTURES_UM")
  symbol            ("BTCUSDT")
  contract_type     ("PERPETUAL")
  price_type        ("LAST" | "MARK")
  timeframe
  source_open_times (масив от open_time на свещите източник,
                     възходящо, цели числа)
  direction         ("BULL" | "BEAR" | null)

ИЗКЛЮЧЕНИ (не влизат в ID-то):
RECEIVE_TIME, LOCAL_RECEIVE_TIME, SERVER_TIME_OFFSET,
VALIDATION_STATUS, MITIGATION_STATUS, DATASET_HASH.

Обосновка: ID-то идентифицира събитието, не наблюдението му.
Статусите се променят чрез нови събития с PARENT_EVENT_ID.

------------------------------------------------------------
51.2 NUMERIC CANONICALIZATION
------------------------------------------------------------

Цени и обеми се пазят като ДЕСЕТИЧНИ НИЗОВЕ точно както ги
връща Binance. Без float преобразуване в хешираните данни.

------------------------------------------------------------
52.1 DATASET_HASH RECIPE
------------------------------------------------------------

DATASET_HASH = "ds_" + hex(SHA-256(ред по ред))

Ред = open_time|open|high|low|close|volume|close_time
      (низове от Binance, разделител "|", завършва с "\n")
Редовете са сортирани по open_time, без дубликати.

Метаданни към хеша: source, endpoint/архив, symbol,
contract_type, timeframe, time_range, data_version.
